## Описание проекта
Проект представляет собой учебную конфигурацию «Мини-Склад», реализованную на платформе **1С:Предприятие 8.3**. В рамках проекта создана структура метаданных: подсистема «МиниСклад», справочники («Товары», «Контрагенты»), документы («Поступление», «Реализация») и регистр накопления («ОстаткиТоваров»).

## Как открыть конфигурацию (порядок загрузки из файлов)
1. Установите платформу **1С:Предприятие 8.3** (рекомендуемая версия 8.3.x).
2. Запустите «1С:Предприятие» (стартер) и нажмите **«Добавить»** → «Создание новой информационной базы».
3. Выберите «Создание информационной базы без конфигурации» и укажите имя базы (например, «Мини-Склад»).
4. Запустите созданную базу в режиме **«Конфигуратор»**.
5. В верхнем меню выберите **Конфигурация** → **Загрузить конфигурацию из файла...** (или откройте папку с выгрузкой через «Открыть конфигурацию» / загрузку XML-файлов).
6. Выберите файлы выгрузки из текущего репозитория и дождитесь окончания загрузки.
7. Нажмите клавишу **F5** для обновления конфигурации базы данных.
## Обновление проекта: Неделя 3 (Партионный учет и ГИС Меркурий)

В рамках третьей недели стажировки в конфигурацию «Мини-Склад» были успешно интегрированы и настроены следующие механизмы:

### 1. Партионный учет и логика FIFO
* В модуле объекта документа **«Реализация»** разработан серверный алгоритм списания запасов по методу **FIFO** (сортировка остатков по дате документа `Поступление` в возрастающем порядке `ВОЗР`).
* Внедрен механизм транзакционных блокировок данных (`БлокировкаДанных`) для предотвращения коллизий при одновременной работе пользователей.
* Добавлен жесткий контроль отрицательных остатков: при нехватке товара на складе проведение документа полностью блокируется платформой с выводом детального сообщения пользователю.

### 2. Интеграция с ФГИС «Меркурий» (Модуль КБ99)
* В пользовательском режиме подсистемы **«кБ99 ВСД»** успешно инициализирован регистр параметров подключения к Ветис.API.
* Выполнена ручная типизация полей ввода значения (переключение на тип «Строка»), что позволило корректно сохранить в информационной базе боевые тестовые реквизиты авторизации (`APIKey`, `Login`, `Password`, `IssuerID`, `ServiceID`).
* Журнал документов **«ВСД2 производство»** успешно подготовлен к работе, структура документов зафиксирована в базе данных для последующей трансляции транзакций.

Полный подробный отчет с анализом структуры запросов и скриншотами тестирования прикреплен к сдаче в файле **`Отчет_Неделя3.docx`**.
